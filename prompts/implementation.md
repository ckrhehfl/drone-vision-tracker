# Codex 구현 작업 프롬프트

아래 내용을 새 구현 작업에 붙여 넣는다. 작업 ID와 목표는 사용자가 선택한다.

---
이 저장소의 AGENTS.md, README.md, docs/01_system_design.md, docs/05_decisions.md, docs/04_implementation_plan.md를 먼저 읽어라.

docs/07_single_camera_operating_envelope.md의 v1.1 기준도 명시적으로 읽어라. 단일 카메라·
기존 2축/전원을 유지하고 거리·스테레오·추가 축·자동 뒤집기·레이저를 구현하지 마라.
해당 모듈이 있을 때 SC01–SC08의 경계/누적 방지/안쪽 복귀/소실/재ARM 동작을 검증해라.
모듈이 없으면 인터페이스·시험 계획으로 남겨라. 실측값을 만들거나 기존 목표/분모를 낮추지 마라.

기본 예시는 미구현 P1 영상 입력 준비다. 사용자가 선택한 작업이 P2 학습/평가라면 그 범위로
맞춰라. 이번 범위와 파일 변경 계획을 제시하고 기존 P0/학습 환경 기록을 보존해라.
카메라·Serial·서보를 자동 가동하지 말고 새 비용·외부 업로드·도구 설치는 기존 승인 기준을 따라라.

새 환경이거나 기존 기록과 다를 때 OS, Python, GPU·VRAM, 드라이버·패키지를 확인해
templates/environment_record.md 형식으로 기록해라. 확인 불가는 추정하지 마라.
이미 검증한 학습 환경은 docs/training.md를 따르고 이유 없이 모델/버전을 교체하지 마라.

P1을 선택했다면 녹화 영상 입력, 프레임 시각, FPS 구분, 오버레이, EOF·오류·정상 종료를
작은 PR로 구현해라. 지정 드론 가중치가 없으면 가짜 검출/일반 영상 파이프라인 검증이라고
명확히 표시해라. P2라면 검수된 데이터·로컬 가중치로 학습/평가하며 실제 정확도 증거를 분리해라.

tests에 재현 가능한 테스트를 추가하고 실행 결과와 미실행 시험을 보고해라. 구현 후 base/head commit, 바뀐 파일, 요구사항, 테스트 결과를 새 독립 리뷰 세션에 넘겨라.
공유 dev-orchestrator 스킬을 따르고, 사용자 요청에 병합이 포함된 경우 최신 CI·독립 리뷰·Decision Gate PASS 후 보호된 PR만 병합해라. main 직접 push나 보호 우회는 하지 마라.
---
