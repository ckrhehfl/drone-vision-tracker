# 맥 GUI 성능 표시와 추적 박스 평가

GUI의 카메라 시작으로 새 측정 세션이 시작된다. 사진 수집은 기본 꺼짐이며,
측정 기록 저장 버튼에서 수치 JSON을 선택한 로컬 경로에 쓴다.
`학습 프레임 수집`을 별도로 선택하면 원본 사진과 수집 종료 시 측정 JSON을 저장한다.
수집·검수·학습 방법은 [재학습 안내](retraining.md)를 따른다.
기존 창은 종료하고 `드론 카메라 실행.command`를 다시 실행한다.

## 화면에서 읽는 값

| 표시 | 의미 |
| --- | --- |
| 수신 FPS | OpenCV `read()`가 성공해 반환한 프레임 수. 센서 자체 FPS는 아님 |
| 화면 갱신 FPS | 새 수신 프레임으로 Tk 영상을 갱신한 횟수. 같은 프레임을 다시 그리면 증가하지 않음 |
| 추적 처리 FPS | 완료한 추적 작업 수. 박스를 못 찾은 작업도 포함 |
| 누적 | 시작 이후 수신/화면 갱신/처리 횟수 |
| 추적 큐·표시 큐·결과 큐 | 최신 항목으로 교체하면서 버린 해당 큐의 항목 수 |
| 오래된 입력 | 처리 시작 때 수신 후 500ms가 지나 버린 프레임 수 |
| 완료 후 만료 | 처리는 끝났지만 수신 후 500ms를 넘겨 박스를 무효화한 작업 수 |
| 처리 p50/p95 | 추적 작업 시작부터 완료까지 걸린 ms |
| 수신→완료 p50/p95 | `read()` 반환 직후부터 처리 완료까지 걸린 호스트 지연. 큐 대기 포함 |

FPS와 지연 분포는 최근 2초 기준이다. 시작 후 2초까지는 실제 경과 시간을 사용한다.
새 이벤트가 없으면 FPS는 0으로 내려가고 지연은 `—`가 된다. p50/p95는 nearest-rank
백분위다. 정지 후에는 마지막 측정 값이 고정된다. 큐별 교체는 서로 다른 사건이므로 합을
‘카메라 드롭 프레임 수’로 해석하지 않는다. 센서·드라이버 내부 누락은 이 방식으로 알 수 없다.
이 호스트 지연은 노출부터 물리적 카메라 움직임까지의 전체 지연이나 Serial ACK 지연이 아니다.

## 기록 저장

1. 카메라를 시작하고 대상을 지정해 시험한다.
2. 정지를 누르고 작업 종료·카메라 해제를 기다린다.
3. `측정 기록 저장`에서 JSON 경로를 선택한다. 카메라를 다시 시작하면 새 세션으로 초기화된다.

기록에는 `session_id`, 장치/모드/임계값/요청 해상도, 성능 값과 수신 프레임별
`frame_id`, 시작 기준 수신 `timestamp_s`, 원본 `width/height`, `processed`, 예측 `box`,
`completed_s`, 추적 `method`가 들어간다. 좌표는 원본 카메라 픽셀의 `[x1,y1,x2,y2]`다.
처리하지 못한 프레임도 `processed=false, box=null`로 남는다. 품질 점수는 정답이 아니다.
기록이 저장되는 동안에는 영상 배열이나 모델 가중치를 직렬화하지 않는다.

메모리를 제한하기 위해 첫 6,000개 수신 프레임의 수치만 보관한다. 이후에도 실시간 측정은
계속하지만 화면에 한도 초과를 표시하고 정확도 평가를 거부한다. 예를 들어 수신 30FPS에서는
약 200초다. 짧은 시험을 정지·저장한 뒤 새 세션으로 시작한다. 잘린 부분을 제외한 성공률을 만들지 않는다.
입력/추적 오류 기록은 저장할 수 있지만 정확도 평가에는 쓰지 않는다.

## 정답 파일과 평가

정답 파일은 **동일한 원본 입력 프레임을 별도로 확인·검수한 박스**로 작성해야 한다.
수동 지정 박스 한 개, 예측 박스 복사, 품질 점수, 화면에 박스가 보이는 횟수를 정답으로 사용하지 않는다.
현재 기능은 라벨 편집기·연속 영상 저장·동영상 입력을 제공하지 않는다. 학습 수집은
0.5초 간격의 일부 원본 사진만 저장하므로 전체 프레임 평가의 정답을 대신할 수 없다. 실제 카메라의 정답을
독립적으로 확보하지 못했다면 속도만 측정하고 정확도는 미검증으로 남긴다.
합성 입력이나 동일 프레임의 정답이 이미 있는 시험에서는 바로 평가할 수 있다.

다음은 3개 프레임을 가진 시험의 형식 예시다. 실제 파일에는 저장된 **모든 frame_id**를 넣는다.
`null`은 지정 대상이 실제로 없는 프레임이며 미라벨링을 뜻하지 않는다.

```json
{
  "schema_version": 1,
  "session_id": "측정 기록의 session_id를 그대로 사용",
  "frames": [
    {"frame_id": 1, "box": [100, 100, 200, 180]},
    {"frame_id": 2, "box": null},
    {"frame_id": 3, "box": [300, 100, 400, 180]}
  ]
}
```

정지 후 `정답 파일로 평가`를 누르면 마지막 세션에 대한 결과가 표시된다.
저장된 기록은 터미널에서도 평가하고 결과 JSON을 남길 수 있다.

```bash
.venv/bin/python -m tools.tracking_metrics --record /path/to/measurement.json --truth /path/to/truth.json
```

| 지표 | 계산 |
| --- | --- |
| 추적 박스 성공률 | IoU ≥ 0.5인 프레임 / 정답 대상이 있는 전체 수신 프레임 |
| 평균 IoU | 대상이 있는 전체 프레임의 IoU 평균. 미처리·미관측은 0 |
| 배경 오인식 | 대상 없는 프레임에 박스가 나타난 수 / 전체 배경 프레임 |
| 전체 잘못된 박스 | 배경 박스와 대상에 충분히 겹치지 않은 박스의 합 |
| Precision | 일치 박스 / (일치 박스 + 잘못된 박스) |
| 재진입 성공률 | 첫 가시 구간 이후 사라졌다가 다시 보인 구간 중 일치 박스를 얻은 비율 |
| 재획득 시간 | 재진입 첫 가시 프레임 수신부터 첫 일치 박스의 처리 완료까지. 호스트 시간 기준 |

재획득하지 못한 구간도 실패로 집계한다. 성공 구간의 시간 p50/p95와 실패를 포함한 전체
재진입 목록을 같이 보고한다. 최초 등장은 재진입이 아니다. 분모가 없으면 `평가 대상 없음`/JSON `null`이다.
정답 누락·중복·세션 불일치·비정상 좌표·잘린 기록·진행 중/오류 기록은 평가를 중단한다.
평가 기준 IoU 0.5와 GUI의 추적 품질 임계값은 서로 다른 값이다.

이 평가는 **전체 수신 프레임 기준의 단일 대상 박스 평가**다. 미처리 프레임을 빼지 않는다.
설계서의 시간 가중 중앙 추종 성공률·1초 정착 기준, 검출 mAP, 실물 팬·틸트 성능을
대체하지 않는다. 일정한 원본 영상 구간을 반복 재생하는 평가는 영상 입력 구현 이후 별도다.
독립 test는 최종 평가까지 격리하고 기준은 validation에서 정한다.
