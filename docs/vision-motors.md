# 드론 비전과 실제 카메라 모터 연결

카메라 GUI의 **카메라 모터**에서 실시간 YOLO 관측을 기존 팬·틸트 제어기에 연결한다.
모터 연결과 구동 허가는 별도 조작이다. 기본 실행은 모의 제어이며 가져오기·영상 시작·
모터 연결만으로 ARM/이동 명령을 보내지 않는다. 동영상 파일과 수동 드래그 모드는 모의 제어를 유지한다.

## 확인된 설치 기준

2026-11-12 사용자 확인: 카메라 기구 장착 완료, 0번은 좌우·1번은 상하 축이며
1번 틱 증가가 위쪽이다. 두 채널의 기본 명령 범위는 **80~330틱**이다.
기존 0번 기준은 틱 감소가 오른쪽이다. 이 방향은 구동 전 운영자가 다시 확인한다.
카메라 하중에 따른 추가 범위·속도·방향 조정은 GUI의 **1번 설정**에서만 한다.
0번 범위와 제어 계수는 이 화면에서 변경하지 않는다.

80~330틱과 설치 보고는 실측 각도·카메라 하중에서의 간섭 시험·2축 조합·폐루프 성능 검증 완료가 아니다.
`calibration.example.json`의 미측정 값과 `completed=false`는 유지한다.
이 경로는 운영자가 직접 감독하는 통합 시운전용이며 전체 MVP 완료를 선언하지 않는다.
내부의 0.72도/틱 눈금은 기존 명령 환산값일 뿐 실제 각도 측정이 아니다.
시작 목표는 펌웨어가 읽어 확인한 현재 PWM 명령이고 산술 중간값205로 자동 이동하지 않는다.

## 펌웨어 준비 — 업로드 전에 확인

필요한 전용 소스는 `firmware/vision_follow/vision_follow.ino`이며 프로파일은 `VISION_TICKS1`이다.
기존 PAN0_TEST1·수동 제어·340틱 실험 스케치와 호환되지 않는다.
포트를 열면 Uno가 리셋될 수 있으므로 **기구 지지·서보 V+ OFF·USB/PCA 논리전원 유지**를
확인하고, 전용 펌웨어 설치를 확인한 뒤 연결한다. USB 분리는 논리전원 손실도 동반할 수 있다.

Arduino CLI1.5.1, AVR core1.8.8, Uno `arduino:avr:uno`를 사용한다.
기본 컴파일은 `VISION_HARDWARE_ENABLED=0`이므로 구동을 거부한다. 실제 설치 빌드는 운영자
확인 후 `compiler.cpp.extra_flags=-DVISION_HARDWARE_ENABLED=1`로 별도 준비한다.
CI는 두 빌드를 컴파일만 하며 실제 포트를 열거나 업로드하지 않는다.

펌웨어는 이미 존재하는 두 PWM의 on=0, off=80..330, MODE1의 AI·SLEEP·외부 클록,
MODE2=4, prescale121을 검사해 출력 쓰기 없이 DISARMED로 이어받는다.
FULL_OFF·잘못된 클록·범위 밖 값·읽기 오류·이전 불확실한 쓰기의 ACK 모드 잔류이면 잠근다.
잠겼을 때 자동 초기화·원점 복귀·전원 재투입으로 우회하지 않는다. V+ OFF에서 기존 명령과
설치 상태를 별도로 확인하고 검토된 복구 절차를 준비한다. 포트 연결을 반복해도 자동 구동하지 않는다.

LOCKED 연결에서는 읽기 전용 DIAG를 한 번 요청해 비활성 빌드·클록·출력 모드·잔류 PWM 조건을
구분하고 오류 표시 후 연결을 닫는다. I²C 읽기 실패도 별도로 표시한다. 진단은 잠금을 해제하거나
PWM·모드를 쓰지 않는다. `-1,-1`은 잔류 명령을 채택하지 않았다는 표시이며 현재 위치가 아니다.
MODE2=12 표식은 정상 시험에서 남았을 수도, 불확실한 부분 쓰기의 흔적일 수도 있으므로
원인 확인 없이 모드만 강제로 바꾸지 않는다. 복구는 기구 지지·V+ OFF에서 별도로 검토한다.

## GUI 조작 순서

1. YOLO 모델과 실시간 카메라를 선택한다. **추적 시작**으로 첫 처리 결과가 나올 때까지 기다린다.
2. **카메라 모터 → 포트 찾기**에서 실제 Uno 포트를 선택한다. 이 단계는 목록만 읽는다.
3. 필요하면1번의 하한·상한을80~330 안에서 좁히고 시험 속도를 조정한다(기본5틱/초, 최대10).
   방향 기본값은 사용자 확인에 따라 **틱 증가 → 위**다. 0번 시험 속도는 기존10틱/초 상한을 유지한다.
4. 기구 지지·V+ OFF·전용 펌웨어 설치를 확인하고 **모터 연결 확인**을 누른다.
   READY·프로파일·범위·현재 명령을 확인하며 ARM이나 SET을 보내지 않는다.
5. 연결 상태를 확인한 뒤 운영자가 V+를 켜고 정착·간섭·두 축 운용 범위·방향을 확인한다.
   전원 인가만으로도 마지막 명령 위치로 움직일 수 있다. 이상하면 외부전원을 차단하고 진행하지 않는다.
6. 확인 항목을 선택하고 **카메라 추종 구동 허가**를 누른다. 첫 영상 처리 전에는 누를 수 없다.
   ARM은 목표 위치를 바꾸지 않는다. 구동 후 새 실제 관측 두 개로 제어를 시작한다.
7. **모터 구동 해제·연결 종료**, 영상 **정지**, 입력 오류·종료 또는 창 닫기는
   제어기를 잠그고 DISARM과 포트 닫기를 요청한다. 다음 구동에는 새 연결과 운영자 확인이 필요하다.

틱 표시와 ACK는 출력 명령 이력이며 실제 위치가 아니다. **HOLD/DISARM은 물리적 비상정지나
PWM·전원 차단이 아니다.** 운영자는 기구를 지지하고 접근 가능한 외부전원 차단을 준비한다.

## 지연·오류와 전체 범위 쓰기

영상 캡처·추론·큐·렌더링·평가 분모는 변경하지 않는다. 실물 경로는 기존 실시간 제어기의
100ms 관측 신선도·포화 방지·안쪽 복귀를 그대로 사용한다. 관측 소실·지연은 HOLD이며
이전 목표까지 계속 접근하는 동작과 구분한다. 지연 HOLD 지표도 기존 세션에 기록한다.

통신은 별도 worker에서 한 요청/ACK씩 최대20Hz로 처리하고, Tk와 추론 작업을 기다리게 하지 않는다.
150ms 응답 제한을 넘기거나 잘못된 응답을 받으면 FAULT로 잠그고 이동 재전송·자동 재ARM을 하지 않는다.
정리용 DISARM만 같은 세션의 유효한 이전 ACK를 원래 deadline 안에서 건너뛴다.
펌웨어는 제어 갱신이500ms 끊기면 목표 진행을 취소하고 잠근다. PING·중복 명령은 이를 연장하지 않는다.

전체80~330틱은255/256 경계를 지나므로 기존 PAN0의 하위 바이트 전용 쓰기를 확대하지 않는다.
전용 펌웨어는 구동 시 PCA9685 OCH=1에서 한 채널의 네 PWM 레지스터를 한 번에 쓴다.
NXP 명세의 마지막 ACK 갱신을 이용하고 부분 오류 뒤 출력이 적용되지 않았다고 가정하지 않는다.
정상 DISARM은 확인된 일관된 출력에서만 STOP 모드로 복원한다. 오류 중에는 ACK 모드를 남겨
리셋 후 자동 인계를 거부한다. 실제 호환 보드의 동작은 현장 시험이 필요하다.
근거: [NXP PCA9685 데이터시트 7.3.2, 주3](https://www.nxp.com/docs/en/data-sheet/PCA9685.pdf).

## 검증 범위와 남은 시험

회귀 검사는 fake Serial, 실제 sketch를 실행하는 native I2C 모형, 제어기→통신→sketch 결합,
GUI의 두 단계 확인·오류 표시·종료 대기를 검사한다. 기본 비활성·범위 밖 거부·양방향 경계 통과·
부분 I2C 적용·watchdog·재연결 잠금·stale HOLD·운영자 확인 전 명령 없음이 대상이다.

실물 설치·카메라 장착 후 양방향·두 축 조합 간섭·소음·전원 강하·실제 UART 지연·
프로세스 중단·USB 단절/복원·실제 카메라 폐루프 추종은 별도 현장 기록이 필요하다.
소프트웨어·컴파일 통과를 이 실물 시험이나 SC01–SC08 전체 완료로 보고하지 않는다.
기존 누적 수정2/2와 이전 전체 리뷰 원문을 보존하며 새 blocker는 세 번째 자동 수정으로 처리하지 않는다.
GitHub 업로드·PR·병합은 별도 요청 전까지 수행하지 않는다.
