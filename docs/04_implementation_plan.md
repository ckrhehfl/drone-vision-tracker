## v1.1 경계 동작 반영

[SC01–SC08 계약](07_single_camera_operating_envelope.md)은 관련 모듈이 생길 때 동작 테스트로
구현한다. 현재는 시험 계획이며 문구 일치 테스트나 가짜 실측값으로 구현 완료를 대신하지 않는다.

| 단계 | 연결할 계약 / 완료 증거 |
|---|---|
| P1/P3 | SC01/SC05/SC06/SC08: 깊이 없는 관측, 실제 검출과 예측 구분, stale/재연결, FPS 의미 |
| P4 | SC01–SC08: MockTransport, 축/2축 허용 영역, 포화와 소실 구분, 누적 방지·안쪽 복귀, 실제 ARM 없음 |
| P5a | SC02/SC06/SC07: 범위 밖 SET 거부, HOLD/모션 watchdog/명시적 재ARM |
| P5b | 축 보정과 별도 2축 운용 범위·간섭·케이블·전원 실측. 미확인 값은 미검증 유지 |
| P6 | 영역 사전 동결, 기존 목표/분모 유지, 영역 내 실패 집계, 제한동작과 추종 성공 분리 |

기존 모듈 경계를 유지하고 미래 스테레오/다축 프레임워크를 만들지 않는다.
머리 위 추적 보장을 위해 급회전·자동 뒤집기·무제한 수색을 추가하지 않는다.

## PR 통과 기준
작업의 요구사항과 실제 변경을 연결하고 테스트 명령·결과·미실행 사유를 기록한다. 리뷰는 별도 Codex 작업에서 수행한다. 하드웨어 시험이 필요하지만 아직 못 한 PR은 ‘하드웨어 검증 대기’로 표시한다. 테스트가 없는데 CI 초록 표시만으로 완료 처리하지 않는다.

수정 재시도는 PR당 최대 2회이며 일반 내부 구조 선택은 에이전트가 결정한다.
한도 초과·범위·비용·권한·실물 등 [운영 규칙](automation/operating-policy.md)의 사유에서만
사람 판단을 요청한다. 자동화의 실제 구축·병합 상태는 [현재 상태](automation/setup-status.md)를 따른다.
