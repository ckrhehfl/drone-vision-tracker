# 0번 팬 축 제어기 시운전

PR #31의 `PanTiltController`를 재사용해 Mock → 0번 소범위 → 1번 개별 보정 → 2축 순으로 진행한다.
기존 카메라 GUI는 계속 MockTransport를 사용한다. 이 도구는 별도 터미널에서 실행한다.
저장 동영상의 캡처·추론·프레임 순서·기존 측정과 평가 기준은 바꾸지 않는다.

## 1. 장치 없는 검사

Python 환경과 Arduino CLI 1.5.1, `arduino:avr@1.8.8`, 호스트 C++ 컴파일러가 필요하다.
macOS에서는 설치된 Arduino IDE의 CLI도 찾는다. Windows CI는 기존 MinGW C++를 사용한다.
추가 라이브러리는 AVR core에 포함된 Wire뿐이다. Python Serial 의존성은 `pyserial==3.5`다.

```bash
python -m pip install -r requirements-dev.txt
arduino-cli core install arduino:avr@1.8.8
python -m tools.ci
python -m tools.pan0_follow
```

마지막 명령은 Serial을 열지 않고 6초간 모의 관측으로 기존 제어기를 실행한다.
기본 200/205/210은 합성 시험값이며 설치된 기구의 승인된 범위가 아니다.
오른쪽 관측 → 왼쪽 관측 → 중심 관측으로 진행하며 목표 포화도 유지한다.

저장된 동영상과 기존 로컬 drone 모델로 시험할 수 있다. 자동 다운로드는 하지 않는다.

```bash
python -m tools.pan0_follow --video /absolute/path/video.avi --model /absolute/path/model.pt --duration 30
```

기존 CameraSession의 정확한 결과/프레임 확인 순서를 사용한다. 제어기는 별도로 호스트 수신 시각과
현재 시각으로 100ms 신선도를 검사한다. 오프라인 영상 시각을 실제 모터의 watchdog 시각으로
사용하지 않는다. 오래된 추론 결과·박스 소실 때 HOLD한다. 결과 대기 중에는 마지막 유효 관측의
100ms 신선도를 확인하고 만료되면 HOLD한다. 20Hz 주기와 60초 이하의
시험 시간만 지원한다. 이는 평가에서 프레임을 제외하거나 지연 지표의 분모를 바꾸지 않는다.

영상 모드에서는 세션 생성과 첫 처리 결과 준비가 끝난 뒤에만 ARM/첫 SET을 보낸다.
준비 시간도 지정한 시험 시간에 포함되며, 준비 실패·종료·시간 만료는 ARM 없이 정리한다.
첫 결과는 한 개만 보관해 원래 captured 시각과 순서로 소비·확인하므로, 준비 중 오래된
프레임은 100ms 기준에서 HOLD하고 시각을 새로 만들지 않는다.
Serial timeout/잘못된 응답 뒤에는 같은 연결의 ARM/SET/HOLD를 잠근다. 정리용 DISARM은
기존 150ms deadline 안에서 같은 세션의 유효한 이전 ACK만 건너뛰고 자기 ACK를 확인한다.
명령 재전송·자동 재ARM·deadline 연장은 없다.

## 2. 현장 준비와 펌웨어

**실물 구동과 업로드는 운영자의 별도 확인 후 수행한다.** 기존 수동 제어/자동 원점 복귀 프로그램을
종료하고 같은 포트를 점유하지 않게 한다. 서보 전원을 끄고 기구를 지지한다. Uno GND와 PCA9685 GND,
A4/SDA·A5/SCL, 외부 서보 전원, 팬 서보의 PCA9685 채널 0 연결을 직접 확인한다.
USB 재연결은 PCA9685의 전원 재투입을 대신하지 않는다. 채널 1은 이번 시험에서 구동하지 않지만
기존 PWM이나 중력 때문에 움직일 수 있으므로 별도로 지지한다.

과거 수동 시험의 임시 팬 눈금은 0/90/180 명령 → 330/205/80틱이다.
실제 각도·완전한 끝단 검증은 아니다. 이 과거 기록만으로 1번 축에 범위를 복사하지 않는다.
현재 설치에서 확인한 최소/시작/최대 틱과 방향을 먼저 정한다. 시작값은 내부에 있어야 하고,
폭은 최대 10틱이며 세 값의 PWM 상위 바이트가 같아야 한다(예: 250..260은 거부).
시작 출력까지의 초기 이동에는 위치 센서나 속도 제한이 없으므로 **현재 기구 위치가 시작값과
일치한다고 현장에서 확인하지 못하면 일반 PAN0 시험을 시작하지 않는다.**
별도로 승인된 두 축 205틱 초기화는 아래 절차를 따른다.

기구를 분리할 수 없고 현재 명령 틱도 모르면 비활성 펌웨어의 부팅 진단
`PWM0,on,off,mode1,mode2,prescale`을 먼저 확인한다. 초기화 전에 읽은 원시 레지스터이며
`on=0`, FULL_ON/FULL_OFF 없음, 유효한 off 범위와 모드·prescale을 대조해야 기존 PWM 명령으로
해석할 수 있다. 읽기 실패나 FULL_OFF이면 숫자를 현재 위치로 추정하지 않는다.
유효한 기존 PWM도 실제 각도·스톨 없음·전원 OFF 후 위치 유지의 증거가 아니므로 운영자 관찰이 필요하다.

펌웨어의 다음 빌드 정의는 기본적으로 0이다. 코드의 기본값을 실물 값으로 바꾸어 커밋하지 않는다.

| 정의 | 값 |
|---|---|
| PAN0_HARDWARE_ENABLED | 현장 승인된 빌드에서만 1 |
| PAN0_MIN_TICKS | 현장에서 확인한 시험 하한 |
| PAN0_START_TICKS | 현재 위치와 맞춘 시작 틱 |
| PAN0_MAX_TICKS | 현장에서 확인한 시험 상한 |

확인 후 컴파일의 `compiler.cpp.extra_flags`에 네 `-D이름=값`을 전달한다.
CI는 기본 비활성 빌드와 합성 프로파일 빌드 둘 다 **컴파일만** 한다.
업로드할 포트·설치된 보드·값·전원 상태를 다시 확인한 후 해당 빌드를 올린다.
부팅 시 유효한 시작 틱과 모드가 정확히 일치하면 PWM 쓰기 없이 DISARMED로 이어받는다.
그 외 활성 상태는 출력 변경 없이 잠근다. 비활성 기본 빌드는 활성 값을 이어받지 않는다.
공유 클록/주파수 변경은 모든 채널에 명시적 FULL_OFF가 있을 때만 허용한다. 초기 쓰기는 FULL_OFF 상태에서
검증 후 허용하고 이후에는 같은 상위 바이트 내 하위 바이트만 1틱씩 갱신한다.
[PCA9685 데이터시트](https://www.nxp.com/docs/en/data-sheet/PCA9685.pdf)의 STOP 시 출력 갱신을 사용하며,
I2C 오류가 나도 마지막 1틱 쓰기가 실제 적용됐을 가능성을 지우지 않는다.

## 3. 0번만 움직여 관찰

실물에서는 `--hardware --port`와 네 프로파일 인자를 **모두** 명시한다.
아래 자리표시자는 확인한 값으로 바꾼다. `direction=1`은 오른쪽 오차에 논리 명령이 증가하고
틱이 감소하는 방향이며 `-1`은 반대다. 이 부호는 설치 상태에서 직접 확인한다.

```text
python -m tools.pan0_follow --hardware --port <확인한 포트> \
  --min-ticks <하한> --start-ticks <시작> --max-ticks <상한> --direction <1 또는 -1>
```

매 연결에서 포트를 열기 전 화면의 `PAN0 하한/시작/상한 방향` 문구를 직접 입력한다.
이후 HELLO에서 펌웨어와 호스트 범위가 일치해야 ARM과 첫 시작 출력이 진행된다.
포트 열기는 Uno 리셋을 일으킬 수 있으므로 이전 펌웨어 상태에서는 연결하지 않는다.
이 펌웨어의 연결·재연결·ARM만으로 이동하지 않는다.
처음에는 6초 합성 관측으로 작은 양방향 움직임을 보고, 이상 없을 때만 위 명령에
`--video ... --model ...`을 함께 붙여 저장 영상의 제어 출력을 확인한다.

Ctrl+C·정상 종료·영상 종료·오류는 DISARM을 요청한다. 불통 시 펌웨어는 500ms 뒤 목표 진행을
취소하고 DISARM한다. 재연결·ACK timeout 후 자동 ARM/재전송/원점 복귀는 없다.
**HOLD/DISARM은 물리적 비상정지나 PWM/전원 차단이 아니다.** 바인딩·소음·예상 밖 방향이면
준비한 현장 전원 차단으로 멈춘다. ACK와 터미널의 틱은 출력 명령 이력이며 실제 위치가 아니다.

관찰 기록에는 프로파일·방향·펌웨어/호스트 SHA·포트·시작 위치·움직임/소음·중지와
USB 분리/재연결 결과를 남긴다. 최소한 양방향·범위 제한·박스 소실 HOLD·프로세스 종료·USB 분리·
연결 복원 시 자동 재시작 안 함을 확인한다. 성공해도 1번 축과 2축 조합·실제 영상 폐루프 추종,
SC01–SC08은 별도 미검증이다. 이 시운전의 실물 증거 누락은 구동 기능의 병합 blocker다.

GitHub에는 소스·문서·테스트만 승인 후 feature PR로 올린다. 로컬 영상·가중치·실행 로그와
설치 프로파일은 올리지 않으며, PR #33의 기존 자동 원점/수동 제어 변경을 포함하지 않는다.

## 4. 승인된 0·1번 205틱 초기화

2026-11-11 사용자가 **두 모터 모두 80~330틱 범위가 안전함을 이미 확인했고, 두 축을 205틱으로
먼저 명령하라**고 지시했다. 이 확인은 이전의 현재 위치 기준 미확보 blocker에 대해
205틱 첫 기준 출력을 별도로 승인한 것이다. 두 축 자동 추종 방향이나 실측 각도 검증을 뜻하지 않는다.

1. 기구 지지와 서보 V+ OFF, Uno USB 연결을 유지한다.
2. 비활성 기본값을 바꾸지 않고 컴파일 정의 `PAN01_CENTER205_ONLY=1`,
   `PAN0_HARDWARE_ENABLED=1`로 CENTER01_205 초기화 빌드를 준비한다.
3. CI·독립 리뷰·Gate 후 검증 업로드한다. 부팅의 두 채널 FULL_OFF와 READY/PROFILE을 확인한다.
4. 승인된 세션에서 ARM, SET 9000/9000, DISARM을 보내 두 PWM 명령을 205로 설정한다.
   외부전원은 아직 OFF다. 오류 응답이면 전원을 인가하지 않는다.
5. 0번 시험을 이어갈 경우 시작 205의 PAN0_TEST1 빌드를 준비·업로드한다. 채널 0의 정확한
   205틱과 모드를 읽어 PWM 변경 없이 DISARMED로 이어받고, 1번의 205틱은 변경하지 않는다.
6. 두 205틱 명령 확인 후 운영자에게 서보 V+ 인가를 요청한다. 첫 인가 때 두 축이 기준으로
   움직일 수 있으므로 움직임·정착·소음·간섭을 직접 관찰하고 이상 시 전원을 차단한다.
7. 관찰된 기준 상태를 기록한 후 0번 소범위 제어기 시험을 진행한다. 1번은 205틱을 유지한다.

첫 이동은 현재 위치를 읽어 작은 이동폭을 보장하는 동작이 아니다. 이번 사용자 확인과
명시적 205틱 초기화 지시에 따라 수행하는 기준 설정이며, 205를 실측 90도나 도달 보장으로 표시하지 않는다.
