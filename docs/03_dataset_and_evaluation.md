# 지정 드론 데이터셋·평가 계획

## 촬영 계획
지정 드론 포함 약 900장 + 빈 배경 약 100장, 총 1,000장을 첫 운영 목표로 둔다. 600~800장부터 실험할 수 있으며 필요한 조건을 보강한다. 이 숫자는 대화에서 정한 작업량 기준이고 성능 보장값이 아니다.

20~25개 정도의 짧은 영상을 촬영한다. 각 영상은 20~40초, 시작 추출 간격은 0.5~0.8초다. 비슷한 프레임은 제거하고 실제 서로 다른 자세·거리·배경을 남긴다. 거리 비율 25/40/35는 드론 있는 장면의 가까움/중간/멀리 배분 예시다.

정면·후면·측면·아래쪽, 수평·수직 이동, 가까워짐·멀어짐, 벽·천장·창문·물건 배경, 밝기 변화, 잠깐 가림을 포함한다. ‘먼 거리’는 감으로만 기록하지 말고 실제 거리와 영상의 기체 bbox 크기도 남긴다.

거리는 사람이 잰 촬영/시험 조건이다. 영상 bbox를 검증 없이 m로 변환하거나 시스템이
거리를 실시간 측정했다고 표시하지 않는다. 단일 카메라·2축 MVP는 거리 입력을 요구하지 않는다.

## 안전한 데이터 확보
초기 외형은 전원 꺼진 기체·프로펠러 분리 상태로 촬영할 수 있다. 비행·프로펠러 회전 영상은 실제 배포 조건을 대표하는 별도 세션에서 확보한다. 회전 중인 기체를 손으로 잡지 않는다. 비행 시험은 운영자와 장소 규정, 보호거리, 지도자의 감독을 따른다. 레이저를 사용하지 않는다.

## 원본 그룹부터 분리
1. 장소·시간·카메라 설치가 연결된 촬영을 session_id로 묶는다.
2. session_id 단위로 train/val/test를 대략 70/20/10으로 먼저 나눈다.
3. 그 뒤 프레임을 추출한다. 같은 세션을 자른 영상도 같은 split이다.
4. 원본 파일·타임스탬프·이미지 해시·split을 manifest에 기록한다.
5. 증강은 train에만 적용한다. 자동 라벨 수정·유사 이미지 제거도 split 경계를 유지한다.

분할 독립성, 일관된 박스와 다양한 장면, 배경 이미지 활용은 공식 데이터 가이드와 맞춘다. 다만 1,000장·촬영 비율은 이 프로젝트의 초기 계획이다. [S4: 06_sources.md]

## 라벨 정책
클래스는 `0: drone`. 가시 기체 전체를 일관되게 감싸되 그림자·손·지지대를 박스에 넣지 않는다. 프로펠러 회전 흔적의 처리 기준은 팀 내 예시 10장을 승인하고 통일한다. 작은 기체는 경계를 판단할 수 있는 것만 라벨링한다. 판단 불가 이미지를 드론 없는 배경으로 바꾸지 않는다.

YOLO 라벨의 정규화 좌표는 선택한 학습 도구의 공식 형식을 확인하고 저장한다. 이미지와 라벨을 겹쳐 보는 검수 도구로 전체를 확인한다. 빈 배경은 클래스 객체가 실제로 0개인 이미지다.

100~200장 수동 라벨 → 초기 모델 → 나머지 초안 자동 생성 → 사람이 전체 검토. 자동 생성 결과를 정답으로 무검수 사용하지 않는다. test 라벨과 시험 장면은 최종 튜닝에서 격리한다.

## 모델 기록
가중치 이름·해시, 기본 모델, 라이브러리 버전, 코드 commit, 입력 크기, epoch, seed, 데이터 버전·split 목록, 학습·검증 지표, 실패 예시를 기록한다. 구체적인 학습 수치는 환경 확인 후 실험으로 정한다.

## 평가 원칙
검출: 독립 test 세션에서 Precision/Recall/mAP50/mAP50–95를 보고한다. 검출 임계값은 validation에서 정한다. 최종 test를 보고 수정하면 그 세트는 더 이상 손대지 않은 최종 test가 아니다.

추종: 유효 가시 시간을 사람이 정의하고 고정 1초 정착 시간을 제외한 나머지 전체 가시 시간을 분모로 한다. 각 시간 구간에서 기체 중심이 너비±5%, 높이±5%의 중앙 허용 영역 안에 있는지 판정한다. 처리 누락·검출 실패를 분모에서 빼지 않는다. 원본 시험 영상의 일정한 평가 간격이나 시간 가중 방식으로 산출하고 보고서에 방식을 적는다.

시험 영역의 위치·거리·높이·경로·속도·조명을 통합시험 전에 고정한다. 기구/명령 허용 범위와
카메라의 현재 시야는 별도로 기록한다. 영역 내 놓침·프레임 드롭·추종 실패를 시스템 성능에
맞춰 사후에 영역 밖으로 재분류하지 않는다. 계획된 영역 밖 시험은 별도 제한동작 시험이며
안전한 HOLD를 추종 성공으로 세지 않는다. 기존 정량 목표와 가시 시간 분모는 유지한다.
[운용 범위](07_single_camera_operating_envelope.md)와 시험 보고서 양식에 원래 시험 조건을 남긴다.

지연: capture_return 시각부터 enqueue 시각까지를 호스트 지연으로 부른다. exposure 시각을 모르면 카메라 전체 지연으로 부르지 않는다. ACK 왕복과 물리적 움직임 완료는 별도다. p50/p95, 입력·처리·출력 FPS를 분리 보고한다.

구조 예시는 `data/README.md`와 `templates/dataset_manifest.example.json`을 참조한다. 영상·사진·가중치는 기본 Git 커밋 대상이 아니다.
