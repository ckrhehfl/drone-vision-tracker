# 드론 추적 GUI · 로컬 시험

맥 내장 카메라 또는 Windows 카메라를 임시 입력으로 사용한다. 기존 USB 카메라·2축 MVP의 최종 시험을 대체하지 않는다.
창을 여는 것만으로 카메라가 켜지지 않으며 **추적 시작** 버튼으로 사용자가 시작한다.
기본적으로 영상은 메모리에서만 처리한다. **학습 프레임 수집**을 선택하면 원본 사진을
지정한 로컬 폴더에 저장한다. 연속 녹화·외부 업로드·Serial·모터 구동은 하지 않는다.

**학습용 영상 가져오기**에서는 외부 로컬 영상 파일에서 0.5초 간격의 원본 프레임을 추출한다.
카메라 연결 없이 사용할 수 있고 추출은 별도 작업에서 실행된다. 종료하면 추출을 취소한다.
완료된 폴더의 라벨과 촬영 그룹을 검수한 뒤 기존 CUDA/MPS 추가 학습으로 이어간다.
구체적인 라벨 형식·계획 파일·명령은 [재학습 안내](retraining.md#외부-동영상-가져오기)를 따른다.

## 화면과 버튼

왼쪽 사이드바의 **추적 / 학습 · 평가**로 작업 패널을 전환한다. 패널을 바꿔도 진행 중인
영상 추적은 유지된다. 창이 작거나 고급 설정을 펼쳤을 때는 왼쪽 패널을 스크롤한다.

| 위치 | 동작 |
|---|---|
| 입력 · 카메라 | 연결된 카메라 선택과 새로고침. 추적 시작을 눌러야 입력을 연다. |
| 입력 · 동영상 | 동영상 선택 후 추적 시작. 파일 선택만으로 재생하거나 저장하지 않는다. |
| 추적 방식 | 자동 검출 / 수동 지정 전환. 임계값은 각각 0.25 / 0.65로 설정한다. |
| 드론 모델 · 선택 | 신뢰하는 로컬 `.pt` 선택. 자동 검출 시작 때 파일을 검사한다. |
| 추적 시작 / 정지 | 선택한 입력을 시작하거나 입력 해제를 요청한다. 해제 완료까지 재시작을 잠근다. |
| 대상 해제 | 실행 중인 수동 지정 대상을 해제한다. 자동 검출에서는 사용할 수 없다. |
| 일시정지 / 재생 | 동영상 테스트의 재생 상태를 전환한다. 카메라에서는 사용할 수 없다. |
| 고급 설정 | 품질 임계값, MPS/CUDA/CPU, 요청 해상도. 실행 중 설정은 잠긴다. |
| 학습 · 평가 | 학습 프레임 수집, 영상 가져오기, 수동 라벨 편집기, 수동 라벨로 모델 학습, 측정 기록 저장, 정답 파일 평가. |

**학습 · 평가 → 수동 라벨 편집기**에서 정상 완료된 수집·영상 추출 폴더를 열어 드론 박스를
그리거나 이동·크기 변경하고 배경/미라벨을 구분해 저장한다. 임시 저장과 검수 완료 저장을 분리하며,
닫기 취소를 선택하면 메인 프로그램도 종료하지 않는다. [라벨 편집과 검수 순서](retraining.md)를 따른다.

**수동 라벨로 모델 학습**은 별도 학습 창을 연다. 검수 완료한 폴더와 촬영 그룹·train/val/test를 지정하고
**새 데이터 준비 → 복사본 확인 → 데이터 검수 완료 → 학습 시작** 순서로 사용한다.
기존 로컬 `.pt`와 CUDA/MPS/CPU/auto, epochs·imgsz·batch를 지정할 수 있다.
데이터 준비·검수 검사·학습은 별도 프로세스로 실행하고 화면에 로그를 표시한다.
추적·영상 가져오기와 학습 작업을 동시에 시작할 수 없다. 창 종료 때 실행 중인 작업의 중지를 취소하면
프로그램이 계속 열린다. 자세한 분할 규칙과 저장 경로는 [GUI 재학습 순서](retraining.md)를 따른다.

영상은 원본 비율을 유지해 가운데 표시한다. 수동 드래그는 영상 영역에서 시작하며,
가장자리 여백을 제외한 원본 좌표로 변환한다. 상단은 실행 상태, 영상 배지는 현재 대상 관측 상태를
표시한다. 하단 **실제 해상도 / 처리 시간 / 대상 관측**은 표시 중인 입력과 유효 관측에서 얻는다.
입력 대기·정지·관측 만료 시 관측 표시와 처리 시간을 지운다. 요청 해상도는 고급 설정에 따로 표시한다.
동영상 일시정지 때 관측 표시는 마지막으로 멈춘 프레임의 관측이며 현재 실물 관측을 뜻하지 않는다.
처리 시간은 해당 추적 처리 시간이며 전체 지연·FPS·정확도와 다르다. 수신·화면·추적 FPS와 지연
분포는 별도 성능 문구에서 확인한다. 모델 학습 실행은 기존 CLI를 유지한다.

## 영상 테스트 · 학습과 분리

1. **추적 → 동영상 → 동영상 선택**에서 로컬 MP4·MOV·AVI·MKV·WebM 등을 선택한 뒤
   **추적 시작**을 누른다.
2. 선택한 로컬 `best.pt`의 `drone` 클래스로 자동 검출하고 박스를 표시한다. 수동 모드였다면
   YOLO 모드·임계값 0.25로 바꾼다. 설치된 공개 모델이 없으면 먼저 신뢰하는 드론 `.pt`를 선택한다.
3. **일시정지 / 재생**으로 관찰하고 **정지**로 중단한다. 같은 영상을 다시 선택하면 처음부터
   새 세션으로 시험한다. 영상 위치·원본 해상도·진행 프레임 수와 기존 성능 표시를 함께 확인한다.
4. 정상 끝까지 재생한 뒤 **학습 · 평가 → 측정 기록 저장 / 정답 파일로 평가**를 사용한다.
   [영상 정답 형식과 평가 기준](tracking-metrics.md#영상-테스트-평가)을 따른다.

카메라 연결 없이 사용할 수 있다. 카메라와 동일한 검출·작은 대상 크롭·재검색 경로와 선택한
MPS/CUDA/CPU를 사용하되, 영상에서는 **모든 프레임을 순서대로 처리하고 해당 프레임에만 박스를 표시**한다.
빠른 영상도 프레임을 버리지 않으며 처리·화면 갱신이 느리면 재생이 느려진다. 원본 영상 시각으로
재생 간격을 제한하고 일시정지 화면은 유지한다. 파일 테스트에는 카메라의 500ms 관측 만료를
적용하지 않는다. 파일 재생 FPS·처리 시간은 실제 카메라의 실시간 성능 보장이 아니다.

이 버튼은 학습·원본 프레임 추출·학습 폴더 생성을 수행하지 않는다. 영상 테스트 중에는
**학습 프레임 수집**을 사용할 수 없다. 학습용 영상 가져오기는 정지 후 별도로 실행하며,
평가 영상은 추가 학습·튜닝용 영상과 촬영 그룹 단위로 분리한다.

지원 확장자라도 설치된 OpenCV가 코덱을 디코딩하지 못하면 오류를 표시한다. 프레임 수·원본 시각을
검증할 수 없거나 중간 디코딩 실패·원본 변경이 발생하면 완료 처리하지 않는다. 중단·오류 기록은
저장할 수 있으나 전체 영상 정확도 평가는 거부한다. 6,000프레임을 넘는 영상도 재생할 수 있지만
현재 측정 기록 한도로 전체 정확도 평가는 불가하므로 짧은 평가 영상을 사용한다.

## 실행

현재 맥의 기존 `.venv`에서 실행한다. Finder에서 `드론 카메라 실행.command`를 더블클릭하거나:

```bash
.venv/bin/python -m tools.camera_gui
```

새 환경은 Python 3.11과 Tk가 필요하다. 기존 [학습 환경](training.md)의 macOS 고정 패키지를 사용한다:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-macos.lock.txt
```

macOS의 시스템 설정 → 개인정보 보호 및 보안 → 카메라에서 실행한 터미널/앱의 접근을 허용한다.
카메라를 사용하는 다른 앱을 닫는다.
설정을 바꾸려면 정지 후 카메라 해제 완료를 기다리고 다시 시작한다. 재시작은 추적 상태를 초기화한다.

Windows는 [Windows CUDA 안내](windows-cuda.md)의 가상환경에서
`.venv\Scripts\python.exe -m tools.camera_gui`로 같은 프로그램을 실행한다.
Windows 카메라 목록은 장치 이름 탐색 대신 0~9번 선택지를 제공하며 실제 연결 여부는 시작할 때 확인한다.
macOS 기본 장치는 `mps`, 다른 운영체제 기본값은 `cpu`다. NVIDIA GPU를 사용하려면 `cuda`를 선택한다.

## 카메라 선택

카메라 번호 대신 **카메라** 목록에서 장치 이름을 선택한다. 맥 내장 카메라가 연결되어 있으면
`Mac 내장 카메라 · 장치 이름`이 기본으로 선택된다. 내장 카메라가 없는 맥에서는 첫 연결 장치를 선택한다.
USB 카메라를 연결한 뒤 **새로고침**을 누르거나 카메라 목록을 펼치면 연결 장치를 다시 조회한다.
`USB 카메라 · 장치 이름`을 선택하고 **추적 시작**을 누르면 해당 장치로 추적한다.
같은 이름의 장치가 여러 개면 `(2)` 등의 표시로 구분하며, 새로고침은 현재 선택한 장치를 유지한다.

추적 중에는 카메라 선택과 새로고침을 잠근다. **정지** 후 카메라 해제 완료를 기다린 뒤 다른 장치를
선택하고 다시 시작한다. 선택한 카메라가 빠졌거나 시작 중 장치 목록이 바뀌면 오류를 표시하고 정지한다.
다른 카메라로 자동 전환하지 않는다. 연결을 확인하고 목록을 새로고침한 뒤 다시 선택한다.
목록을 읽지 못하거나 연결된 카메라가 없으면 시작 버튼을 비활성화한다.
목록 조회는 장치 정보만 읽으며 카메라 영상을 켜거나 녹화하지 않는다.
macOS 외 환경에서는 기존 0~9 번호 선택을 유지하며 연결 여부를 미리 검사하지 않는다.

USB 연결 후 내장·외장 카메라 목록이 모두 사라졌다면 먼저 GUI를 종료하고 수정된 버전으로
다시 실행한 뒤 **새로고침**을 누른다. macOS 장치 목록을 정렬할 때 JavaScript 배열 대신
네이티브 NSArray를 사용해 정렬 오류로 전체 조회가 실패하던 문제를 수정했다.
그래도 조회할 수 없으면 macOS 시스템 정보의 카메라·USB 항목에 장치가 보이는지 확인한다.
목록 표시와 실제 영상 수신은 별도 검증이며, 권한·코덱·입력 해상도 문제는 추적 시작 후 확인한다.

카메라를 켜지 않고 목록 조회만 검사하려면 저장소 루트에서 다음을 실행한다.
출력에는 macOS가 인식한 연결된 카메라 이름이 모두 있어야 한다.

```bash
.venv/bin/python -c 'from tools.camera_gui import list_cameras; print([d["name"] for d in list_cameras()])'
```

## 고해상도 입력과 작은 대상 크롭

입력 해상도 기본값은 **1920×1080**이다. `입력 해상도`에서 1280×720 또는 640×480도
선택할 수 있고, 변경은 정지 후 다시 시작할 때 적용된다. 카메라에 해당 모드를 요청하며
지원하지 않는 장치는 다른 해상도를 전달할 수 있다. 화면에 요청 해상도와 **실제 프레임 해상도**를
함께 표시한다. 입력 FPS는 보장하지 않는다.

미리보기만 창 크기로 축소한다. 추적에는 실제 카메라의 원본 프레임을 사용한다.
수동 지정에는 로컬 ViT 추적기와 특징점/외형 재검색을 사용한다. ViT에는 원본 프레임을 전달하며
추적기 내부에서 대상 주변을 잘라 처리한다. 특징점과 지역 재검색 영역은
최소 640×640이며 큰 목표는 외형의 약 3배 범위로 넓힌다. 카메라 경계에서는 영역을 이동·제한한다.

YOLO에서는 드론의 가로·세로 비율이 각각 화면의 8% 이하일 때 작은 대상으로 취급하고
주변 영역을 크롭한다. 작은 대상의 640×640 크롭은 프레임 전체를 640으로 줄이는 과정에서
잃을 수 있는 세부 정보를 유지한다. 이 기준은 실제 미터 단위 거리 측정이 아니다.
크롭 검출 좌표는 원본 카메라 좌표로 되돌려 박스와 중심 오차를 표시한다.
파란 검색 영역과 상태의 `크롭` 표시로 현재 처리 영역을 확인할 수 있다.

수동 모드에서 새 관측을 놓치면 최근 관측 외형으로 같은 크기의 지역 검색을 먼저 시도하고,
실패하면 **해당 프레임의 원본 전체 화면을 즉시 검색**한다. 전체 화면의 빠른 재검색에는
임계값과 0.8 중 더 높은 점수를 요구한다. 성공 전까지 박스는 관측 소실로 처리하며,
전체 화면 재검색 실패는 기존의 작은 대상 원본 크롭 검색을 방해하지 않는다.
이 재검색은 크기를 바꾸지 않는 한 번의 검색이므로 빠르게 이동한 같은 외형을 찾을 때 사용한다.

화면 밖으로 나가도 **처음 지정한 외형과 마지막 정상 관측 외형**을 메모리에 유지한다.
대상을 놓친 이후에는 새 프레임마다 원본 전체 화면에서 최근 외형을 먼저 찾고, 실패하면
처음 외형도 찾는다. 2초 소실로 위치·추적기를 초기화해도 외형은 지우지 않는다.
재진입한 대상을 찾으면 `재획득`을 표시하고 새 위치에서 특징점·ViT 추적을 재개한다.
첫 재진입 후보는 바로 확정하지 않는다. `재진입 후보 확인 중 · 다음 관측 대기`를 표시하고
500ms 안에 다음 새 프레임에서도 특징점 이동이나 외형 일치를 관측해야 박스를 표시한다.
작은 대상처럼 특징점이 부족하면 후보의 실제 크기로 원본 지역·전체 화면을 다시 매칭한다.
후보가 사라지거나 확인 시간이 지나면 다시 검색하며, 확인 전 후보로 최근 외형이나 ViT를 갱신하지 않는다.
찾지 못한 동안에는 박스 없이 `지정 대상 재검색 중 · 재진입 대기`를 표시한다.
화면 경계에 닿거나 잘린 박스, 무늬가 없는 영역, 500ms를 넘긴 관측으로 최근 외형을 갱신하지 않는다.
외형은 파일에 저장하지 않으며 새 지정·`대상 해제`·정지·입력 해상도 변경으로 초기화한다.

1초 동안 새 관측이 없으면 전체 화면 검색과 겹치는 원본 640×640 구역의 여러 크기 검색을 순환한다.
구역 하나마다 새 프레임을 사용하고 대기열을 누적하지 않는다. 따라서 화면을 한 바퀴
검색하는 데 여러 추적 갱신이 필요하며 재획득이 즉시 이루어지는 것은 아니다. 수동 모드에서는
한 바퀴마다 최근 외형과 처음 외형을 번갈아 여러 크기로 검색한다.
수동 모드의 넓은 여러 크기 검색은 긴 변을 최대 960으로 축소한다. 빠른 전체 화면 재검색과 작은 대상 구역은 원본 픽셀을
유지한다. YOLO도 전체 화면 검출과 구역 검출을 순환해 처음부터 작은 대상을 찾을 수 있게 한다.
입력 해상도가 실행 중 바뀌면 기존 대상 상태를 초기화하므로 수동 대상을 다시 지정해야 한다.

크롭은 새 픽셀 정보를 만들어 내지 않는다. 원본에 드론 외형이 없을 정도로 작거나 흐리면
추적할 수 없으며 실제 원거리 정확도·FPS·카메라 지원 모드는 실물 확인이 필요하다.

## 수동 지정: 범용 추적과 재검색

1. `수동 지정`, 임계값 `0.65`에서 카메라를 시작한다.
2. 영상 안의 드론 외형을 마우스로 드래그해 지정한다. 최소 12×12 원본 픽셀이다.
3. 일치하는 영역에 박스·중심 연결선·픽셀 오차가 표시된다. 오른쪽/아래 방향이 양수다.
4. `대상 해제`로 지우거나 다시 드래그한다. `정지`는 카메라를 해제하고 창을 유지한다. 오른쪽 아래 `종료` 버튼이나 창 닫기는
   카메라 해제와 추적 작업 종료를 기다린 뒤 프로그램을 닫는다.
   종료 대기 중에는 새 카메라 세션을 시작하지 않는다.

현재 맥에는 [OpenCV Zoo ViT 모델](../models/vittrack.md)을 로컬에 준비했다.
일관된 특징점 관측이 있으면 그 이동·크기를 우선 사용한다. 특징점 추적이 실패하면
지정 영역의 사전학습된 범용 ViT 추적기로 이동·크기·외형 변화를 관측한다.
품질이 임계값 미만이거나 좌표가 유효하지 않으면 해당 관측을 버리고 외형 재검색을 시도한다.
특징점·ViT·외형 검색의 모든 관측을 처음 지정한 영역 중앙의 색상 분포와 비교한다.
회색 무늬가 비슷하더라도 색상이 크게 다른 배경은 거부하고, 원래 색상 기준은 실행 중 갱신하지 않는다.
소실 중 ViT 갱신을 중단하고 재획득 확인 후 다시 초기화해 배경으로 추적 기준이 바뀌는 것을 줄인다.
전체 화면이나 소실 후 외형 매칭에 비슷한 점수의 다른 위치가 있으면 해당 후보를 거부한다.

외형 매칭이 실패하면 대상 색상이 있는 영역에서 ORB 특징점을 대응시키고,
서로 일치하는 점들의 기하 변환으로 회전·크기 변화가 있는 대상을 찾는다. 분산된 대응점이
8개 이상이고 변환·좌표·일관성이 유효한 경우만 사용한다. 처음 지정한 형상을 우선해
회전한 최근 크롭의 여백 때문에 재진입 박스가 점점 커지는 것을 줄인다.
가로·세로 변화를 각각 추정해, 이동하면서 몸을 돌리는 경우처럼 폭과 높이의 변화가 다른 외형도
찾는다. 뒤집힌 변환이나 과도한 비틀림은 거부하며 기존 색상·품질·재진입 확인 조건을 유지한다.
재검색 성공 후에는 새 관측으로 ViT를 다시 초기화한다. 상태에서 `ViT`, `특징점`,
`빠른 재검색`, `특징점 재검색`, `템플릿`, `재획득`을 구분한다. 모델 파일이 없으면 입력 정보에 `ViT 모델 없음`을
표시하고 특징점/템플릿을 사용한다. GUI에서 모델이나 패키지를 자동 다운로드하지 않는다.
장치 `mps` 또는 `cuda`를 선택하면 같은 로컬 ViT 모델을 PyTorch로 변환해 Apple 또는 NVIDIA GPU에서 추론한다.
변환은 각 GPU 백엔드의 첫 시작 때 메모리에서 한 번 수행하며 고정 크기 입력으로 최적화·예열한다.
정지·재시작 때는 이 읽기 전용 모델을 재사용해 반복 변환에 따른 GPU 메모리 증가를 막는다.
대상 외형·위치·품질 상태는 세션마다 새로 만들며, 재사용 전에도 원본 모델 해시를 검사한다. 준비 중에는
`ViT MPS 준비 중` 또는 `ViT CUDA 준비 중`을 표시하며 잠시 추적·미리보기가 지연될 수 있다. 모델이나 영상을
저장·다운로드하지 않는다. 입력 정보에 `특징점 CPU + ViT MPS/CUDA`의 선택 장치를 표시한다. `cpu`에서는 기존
OpenCV ViT를 사용한다. 특징점·템플릿·ORB 재검색과 영상 크롭/리사이즈는 CPU에 남으며,
기존 품질·색상 검증·재진입 확인·500ms 제한을 유지한다. GPU 사용 불가나 추론 오류는 표시하고
정지하며 CPU로 조용히 전환하지 않는다. 정지 후 `cpu`를 선택하면 기존 방식으로 다시 시작한다.
실제 추적 속도와 정확도 향상은 실물 시험 전이다. 사용자가 지정한 객체를 추적할 뿐,
드론 클래스 판별이나 인물의 신원 확인은 수행하지 않는다.

특징점 방식에서는 선택 영역 안의 점들을 앞뒤 프레임으로 왕복 추적하고, 서로 일치하는 점들의
이동·크기 변화로 박스를 갱신한다. 지정 경계의 배경을 덜 포함하도록 내부 영역에서 점을 고른다.
특징점 이동에서도 가로·세로 배율을 따로 측정해 방향 전환 중 박스가 같은 비율로만 변하는 것을
줄인다. 급격한 변형이나 팔·몸이 서로 다르게 움직이는 경우에는 한 변환으로 설명하지 못할 수 있다.
유효한 점이 6개 미만이거나 점들의 분포·일관성·변환이 불충분하면 그 결과를 버리고 외형 검색으로
돌아간다. 품질은 원래 점 중 일관된 움직임에 참여한 점의 비율이다. 특징점이 없는 작은 대상은
외형 검색을 사용한다. 수동 임계값은 ViT 점수·특징점 품질·재검색 외형 점수에 각각 적용되며
서로 같은 척도나 인식 확률이 아니다. 높은 점수가 인물·드론의 신원을 보장하지는 않는다.

재검색에서는 기억한 외형을 여러 크기로 축소·확대해 매칭한다. 원래 크기의 일치 점수가 충분히
높으면 나머지 크기 검색을 생략한다. 드론이 멀어져 작아지거나 가까워져 커져도
지정할 때 크기의 0.1~2배 범위에서 약 10% 간격으로 찾고, 가장 잘 맞는 크기 주변을 1픽셀 간격으로 세밀하게 검색한다.
추적 박스 크기도 바뀐다.
가로·세로가 각각 최소 8 원본 픽셀인 경우만 검색한다. 처음 지정은 기존처럼 최소 12×12다.
드론임을 자동 판별하지 않으며 큰 자세 변화·가림·비슷한 배경에서 실패하거나 잘못된 영역을 선택할 수 있다.
인물로 임시 시험할 때에는 배경을 많이 포함한 전신 박스보다 얼굴 또는 무늬가 있는 상체를
좁게 지정한다. 사람용 검출 모델이나 장기 신원 추적기는 아니며, 재진입 시 모습이 기억한 두 외형과
크게 다르면 재검색에 실패할 수 있어 다시 지정해야 한다. 비슷한 다른 대상에 잘못 붙을 수도 있다.
색상 검증과 두 관측 확인도 신원을 보장하지 않는다. 조명·노출·대상 색상이 크게 바뀌면
정상 대상이 거부될 수 있으므로 현재 모습으로 다시 지정한다. 배경이 많이 포함되지 않도록 지정한다.
작은 목표는 세부 정보가 사라져 오인식이 늘 수 있다. 임계값을 낮춰 계속 붙어 있는 것을
추적 성공으로 취급하지 않는다. 최대 몇 미터인지나 거리 증가 중 연속 성공률은 실물 시험 전이다. 점수는 인식 정확도나 확률이 아니다.
목표가 사라지거나 잘못 붙으면 다시 지정한다. 무늬가 없는 영역은 지정하지 못한다.
대상 해제·재지정·재시작 이전 프레임의 늦은 추적 결과는 표시하지 않는다. 새 지정 뒤에는
그 시점 이후에 수신한 프레임의 관측부터 박스를 표시해 이전 대상 박스가 다시 뜨는 것을 막는다.

## YOLO 자동 검출

[공개 쿼드콥터 모델](../models/seraphim-yolov8n.md)을 설치하면 GUI를 다시 열 때
해당 파일·YOLO 자동 검출·임계값 0.25를 기본 선택한다. 설치가 없거나 해시가 다르면 수동 지정으로
시작한다. 카메라는 직접 시작하며 자동 검출·추적 시작은 모델을 다운로드하거나 학습하지 않는다.
추가 학습은 별도의 **수동 라벨로 모델 학습** 창을 사용한다. 인물 시험은 수동 지정을 사용한다.
방식을 바꾸면 임계값을 수동 0.65 / YOLO 0.25로 설정한다.

실시간 수신·화면 갱신·추적 처리 FPS와 큐 교체 수, 처리/호스트 지연 p50/p95를 따로 표시한다.
정지 후 수치 기록 저장·정답 박스 평가를 사용할 수 있다. 기록 한도와 계산 기준은
[측정·평가 안내](tracking-metrics.md)를 따른다. 모델 품질 점수를 정확도로 표시하지 않는다.
`학습 프레임 수집`은 기본 꺼짐이며 선택한 로컬 폴더에 주기적으로 원본 사진을 저장한다.
정지·종료 후 측정 JSON과 라벨 초안도 남긴다. [YOLO 재학습 안내](retraining.md)를 따른다.

신뢰하는 로컬 드론 검출 학습 `best.pt`를 선택하고 `YOLO 자동 검출`, 임계값 `0.25`로 시작한다.
`drone` 클래스가 없는 일반 모델은 거부한다. 모델을 다운로드하거나 자동 학습하지 않는다.
현재 로컬에는 지정 드론용 검증된 가중치가 없어 자동 검출의 실물 성능은 미검증이다.
macOS 장치 기본값은 `mps`, Windows 기본값은 `cpu`다. Windows NVIDIA PC에서는 `cuda`를 선택한다.
명시한 GPU를 지원하지 않거나 추론이 실패하면
정지 후 `cpu`를 선택해 다시 시작한다. 같은 장치 선택이 수동 ViT 추론에도 적용된다.

처음에는 최고 점수 박스 하나를 선택하고 다음에는 기존 박스와 IoU 0.3 이상인 관측 중
가장 많이 겹치는 박스를 우선 연결한다. 겹침이 같을 때는 모델 점수로 선택한다.
배경을 크게 감싼 높은 점수의 박스로 전환하는 것을 줄이며, 일치하는 관측이 없으면
해당 프레임은 박스 없이 관측 소실로 표시한다. 급격한 이동·크기 변화도 소실될 수 있다.
YOLO에서 관측을 놓치면 해당 프레임부터 박스·중심 연결선·중심 오차를 지우고
`대상 소실 · 재검색`을 표시한다. 추적 정보 갱신을 중단하면서 영상 입력과 현재 시야 검색은 계속한다.
2초 소실 뒤에는 이전 위치 연결을 해제하여 다른 위치의 후보도 찾는다.
다만 마지막 정상 박스의 면적을 기억해 그 4배를 넘는 재획득 후보는 제외한다. 위치 연결이
풀린 뒤에도 갑자기 화면 전체로 커진 배경 박스를 받아들이지 않기 위한 제한이다.
실제 드론이 훨씬 가까워져 이 크기를 넘으면 정지 후 새 세션에서 다시 시작해야 한다.
다시 보인 후보는 원본 좌표에서 서로 IoU 0.3 이상인 **3개 새 처리 프레임을 0.5초 안에**
확인한 뒤 `재획득`으로 복귀한다. 확인 중에는 `재획득 확인 중 (1/3)`, `(2/3)`을 표시하고
관측 박스나 중심 오차를 출력하지 않는다. 후보를 확인하는 동안에는 그 주변을 검색하고,
후보 소실·불일치·시간 만료·입력 해상도 변경·오래된 입력/결과는 확인을 초기화한다.
확인 대기 자체가 마지막 정상 관측 시각을 연장하지 않는다. 카메라는 프레임 수신 시각,
동영상은 원본 영상 시각을 사용하므로 느린 파일 처리나 일시정지 시간을 확인 시간으로 세지 않는다.
첫 실행의 초기 검출은 기존처럼 최고 점수 박스 하나를 선택한다. 빠른 이동·다중 드론에서
ID 연속성을 보장하지 않으며, 세 번 반복되는 배경 오검출도 남을 수 있다.
이 정지는 GUI의 추적 정보 갱신 중단이다. 현재 Serial·모터 제어 런타임이 없어 실물 정지나
물리적 HOLD 완료를 뜻하지 않는다. 실제 장치의 정지는 별도 구현·승인·실물 검증이 필요하다.
예측만 있는 박스는 표시하지 않는다. 실제 지정 드론 한 대로 시험한다.
사용 중 모델·임계값·카메라 변경은 다음 시작 때 적용된다.

## 지연과 검증 경계

캡처·미리보기·추적 처리를 분리하고 각 대기열은 최신 한 개만 유지한다.
미리보기는 최신 카메라 영상으로 약 30ms마다 갱신을 시도하며 추적 검색 완료를 기다리지 않는다.
추적 박스는 마지막 유효 관측이며 현재 영상과 시간차가 있으므로 관측 경과 시간을 함께 표시한다.
관측 수신 후 500ms가 지나거나 해상도가 달라지면 박스를 지운다. 카메라 영상 자체가
500ms 넘게 들어오지 않으면 화면을 지운다. CPU 부하나 실제 카메라 조건에 따라 표시 속도는 달라진다.
수동 지정 드래그 동안에는 선택용 화면이 잠시 고정된다.
시각은 OpenCV 프레임 수신 직후이며 센서 노출 시각이 아니다. 표시하는 처리 시간과 수신 후 경과
시간은 실제 카메라 FPS나 프로젝트의 호스트 지연 p95를 대신하지 않는다.
500ms는 임시 미리보기 제한이며 설계의 100ms 제어 성능 목표를 변경하지 않는다.

하드웨어 없는 검사는 `python -m tools.ci`다. 실제 카메라 권한·영상·드론 검출 품질·연속 추적·
FPS·장치 해제는 사용자가 실물로 확인해야 한다. 서보·팬/틸트 추종과 SC01–SC08은 이 GUI의 완료 항목이 아니다.
